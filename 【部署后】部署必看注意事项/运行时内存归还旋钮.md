# 运行时内存归还旋钮（TCMALLOC_RELEASE_RATE）

**本文件只管部署后**：这是 compose 环境变量里的一条设置，重新部署/重装后必须按本文补回，否则内存会随时间缓慢积累。

## 这条设置管什么

运行时（workerd）每次被触碰（工作流执行、面板访问、管理调用）都会留下一点内存"尾费"；它的内存管理器 **tcmalloc 默认几乎不把垃圾退还给系统**，于是占用只进不出、随时间积累（实测慢性增速约 6 MB/小时，长驻几天涨一两百兆）。

`TCMALLOC_RELEASE_RATE` 是 tcmalloc 自带的"归还积极性"旋钮（默认 1.0，数值越大越积极）。设成 10 后，垃圾会被积极退还。

## 怎么设置

compose（`compose.yaml` 或迁移项目里对应文件）的 `open-compute` 服务加：

```yaml
    environment:
      TCMALLOC_RELEASE_RATE: "10"
```

改完 `docker compose up -d open-compute` 重建生效（新增环境变量会触发容器重建，属预期）。

## 实测对比（2026-10-24 凌晨，同一台机、同款负载、同一测量口径）

| 测量点 | 无旋钮（上游默认） | 有旋钮（=10） |
|---|---|---|
| 一次工作流执行后净增 | **+13.4 MB，且实例删除后仍不退还** | **+1.0 MB**（降幅 92%） |
| 删除实例后静置数分钟 | 保持高位 | 稳定低位（容器总量约 104 MB） |
| 深夜零活动时段 | 近乎零增长 | 近乎零增长 |

## 验证方法

```bash
# 看旋钮是否注入成功（应输出 TCMALLOC_RELEASE_RATE=10）
docker exec open-compute sh -c 'for p in /proc/[0-9]*; do grep -q -- "--binary" $p/cmdline 2>/dev/null && tr "\0" "\n" < $p/environ | grep TCMALLOC; done'
```
